# Hydraulic power unit: S1000D technical publication

Maintenance data for the Varnholt VH-15, a fictional 5.5 kW industrial hydraulic power unit,
written to **S1000D Issue 7**. The data module list is derived from the product's bill of materials,
and every data module is checked automatically against the schema, the project's business rules,
and its numbering system.

**Status:** pilot complete. All 17 pilot data modules are written, covering the whole unit, the
reservoir, and the return filter, with two illustrations and two product variants; 52 data modules
are planned in all.

**[Read the maintenance manual](html/index.html)**, rendered from the XML source.

## How it's built

Each step's output is the next step's input, so a change to the BOM flows through to the list of
data modules that need writing or review.

| Step | Input | Tool | Output |
|---|---|---|---|
| 1. Bill of materials | CAD export: indented BOM, 45 parts in 3 levels | none | [`bom/VH15-0000_BOM.csv`](bom/VH15-0000_BOM.csv) |
| 2. Structure and maintenance decisions | BOM | none (engineering judgment) | Project SNS and part-to-SNS map in [`sns/`](sns/) |
| 3. Data management list | BOM, SNS, map | [`tools/make_dml.py`](tools/make_dml.py) | [`dml/VH15-DML.md`](dml/VH15-DML.md), [`dml/coverage.md`](dml/coverage.md) |
| 4. Business rules | SNS, information code list | [`tools/make_brex.py`](tools/make_brex.py) | Project BREX data module (information code 022) |
| 5. Data modules | DML | written by hand in ASD-STE100 style; shells from `s1kd-newdm` | [`csdb/`](csdb/) |
| 6. Illustrations | Product geometry | [`tools/make_figures.py`](tools/make_figures.py) | Shaded isometric SVG drawings named by ICN, with numbered callouts |
| 7. Illustrated parts data | BOM, illustrations | [`tools/make_ipd.py`](tools/make_ipd.py) | Parts lists whose item numbers match the BOM and the figure callouts |
| 8. Publication module | Data modules | [`tools/make_pm.py`](tools/make_pm.py) | The manual's structure: one section per system, descriptions before tasks |
| 9. Checks | Data modules, publication module | [`tools/check.sh`](tools/check.sh) | Pass or fail |
| 10. Rendering | Publication module, data modules | [`tools/render_site.py`](tools/render_site.py) | [`html/`](html/index.html): a contents page and one page per data module, styled with the portfolio CSS |

## Product variants

The unit is supplied with 24 V DC or 230 V AC coils on the directional valve. The applicability
cross-reference table (ACT) declares that attribute once, and content that differs between the two
variants carries an applicability annotation instead of being copied into a second data module. The
rendered pages label it, for example on the [function description](html/DMC-VH15-A-00-00-00-00A-042A-A.html).

## What the checks catch

| Problem | Caught by |
|---|---|
| A bought part has no maintenance decision, so no procedure covers it | Coverage report (`make_dml.py`) |
| A data module breaks the S1000D schema | Schema validation (`s1kd-validate`) |
| A code or value the project doesn't allow, such as an information code outside the DML | Project BREX, layered on the Issue 7 default BREX (`s1kd-brexcheck -l`) |
| A data module code that points outside the product structure | SNS check (`s1kd-brexcheck -S`) |
| A figure referenced but not declared, or a misspelled ICN | Schema validation of the entity reference |
| Variant content that uses a value the ACT doesn't define, or a variant combination that breaks the schema | Applicability check (`s1kd-appcheck -s`) |

The coverage report lists 11 undecided parts on purpose: it shows the check doing its job.

## Folder layout

| Folder | Holds |
|---|---|
| `bom/` | The BOM export |
| `sns/` | Project SNS and the part-to-SNS map |
| `dml/` | Generated data management list and coverage report (don't edit) |
| `csdb/` | The data modules and the publication module, plus the CSDB settings written by `s1kd-defaults` |
| `html/` | The rendered manual (generated; don't edit) |
| `tools/` | Generators, checks, renderer, and the XML catalog for offline validation |

## Tools

Everything is built from the command line, with no desktop publishing or drawing program:

| Tool | Used for |
|---|---|
| s1kd-tools (`s1kd-defaults`, `s1kd-newdm`, `s1kd-newpm`) | Creating the CSDB, data module shells, and the publication module |
| s1kd-tools (`s1kd-validate`, `s1kd-brexcheck`, `s1kd-appcheck`) | Schema, BREX, SNS, and applicability checks |
| Python 3, standard library only | Generating the DML, BREX, figures, parts data, and publication module, and rendering HTML |
| SVG generated by script from 3D coordinates | Illustrations: no CAD or drawing program. The visual style follows a concept image generated with Gemini; its callouts didn't match the parts lists, so the figures were redrawn rather than used as is |
| VS Code with the Red Hat XML extension | Writing the data modules, with live schema validation |
| Git | Version control, one commit per step |

## Build and check

Requirements: [s1kd-tools](https://github.com/kibook/s1kd-tools) 6.x, Python 3, and the Issue 7
flat schemas in `etc/s1000d-schemas/` at the repository root. The schemas aren't included; download
the Issue 7 package from the S1000D website.

```sh
python tools/make_dml.py    # rebuild the DML and coverage report
python tools/make_brex.py   # rebuild the project BREX
python tools/make_figures.py # redraw the illustrations
python tools/make_ipd.py    # rebuild the parts data from the BOM
python tools/make_pm.py     # rebuild the publication module
sh tools/check.sh           # schema, BREX, SNS and applicability checks
python tools/render_site.py # render the manual to html/
```

Open `hydraulic-power-unit.code-workspace` in VS Code with the Red Hat XML extension to get
schema validation and completion while editing.

## Limits

- The model identification code `VH15` isn't registered with NSPA, and the manufacturer code `VH000`
  isn't a registered CAGE code. Both are placeholders for a fictional product.
- The SNS is defined for this project, not taken from one of the maintained SNS in the specification.
- The CSDB is a folder managed with s1kd-tools, not a commercial CSDB product.
- The illustrations are drawn by script from simplified geometry, not exported from a CAD model.
- The ACT defines one product attribute, the directional valve coil voltage (24 V DC or 230 V AC). The
  BOM shows the 24 V DC configuration only.
